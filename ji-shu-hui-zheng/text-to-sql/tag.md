# TAG

## 緒論

### 使用自然語言查詢資料庫

LLM 的進步促使 Text2SQL 和檢索增強生成（RAG）的研究，但現有的方法不足以探索這個場景。

* **Text2SQL**：僅可用於關係代數表達的自然語言問題，但僅占實際使用者想問問題的一小部分。
* **RAG**：只考慮可以透過查找資料庫中一筆或幾筆資料記錄來回答的查詢。

### 領域知識

實際商業使用的問題通常需要結合領域知識、世界知識、精確計算和語義推理。 資料庫系統顯然透過其儲存的最新資料提供領域知識，以及大規模的精確計算能力（但這是 LLM 不擅長的）。LLM 擁有文字資料的語義推理能力，這是許多自然語言使用者查詢的核心要素。例如，情緒分析或趨勢摘要。

## TAG 模型

表格增強生成（Table-Augmented Generation，TAG）作為回答資料庫自然語言問題。

* TAG 定義了三個關鍵步驟：查詢合成、查詢執行和答案生成。
  * 查詢合成（syn）： 將使用者的任意自然語言請求 R 翻譯成可執行的資料庫查詢 Q。
  * 查詢執行（exec）： 在資料庫系統上執行 Q 以有效地計算相關資料 T。
  * 答案生成（gen）： 利用 R 和 T，LLM 能以迭代或遞迴模式對資料進行編排，以生成最終的自然語言答案 A。
* TAG 模型由三個公式定義，但涵蓋了 LLM 和資料庫之間先前未經充分研究的廣泛交互作用。
* TAG 模型統一先前的方法，包括 Text2SQL 和 RAG，代表了 TAG 的特殊情況，並且僅服務於有限的使用者問題子集。

## TAG 設計空間

* 基礎資料模型採用多種形式，使用關聯式資料庫來儲存和檢索結構化屬性，以便在下游問答任務中進行知識基礎。其他模型可能對非結構化資料（例如，自由文字、圖像、影片和音訊）或半結構化資料進行操作，這些資料可以使用各種資料模型儲存，例如鍵值、圖形、向量、文件或物件儲存。
* 資料庫執行引擎和 API 可以使用許多可能的資料庫執行引擎。 Text2SQL 考慮使用基於 SQL 的查詢引擎來檢索使用者查詢的關聯式資料。
  * syn 將利用資料來源的知識（例如表格結構描述），並返回一個 SQL 查詢來執行檢索步驟。
  * 透過向量嵌入進行檢索的系統中，syn 將自然語言查詢轉換為嵌入，而 exec 則對向量儲存執行基於相似性的檢索。
  * 給定相關資料表 T，gen 可以由大量的實現決策組成，以生成最終的自然語言答案 A 來回應使用者請求 R。

## 評估

資料來源中的資料回答的基本查詢上的表現。 本文透過修改查詢來擴展先前的工作，使它們需要模型回答資料源中沒有直接提供的知識或語義推理。

### Dataset&#x20;

* 選擇 BIRD 作為查詢的資料來源， 因為它具有大規模的表格及其多樣化的領域和查詢類型。
* 結果顯示，在選定的 BIRD 查詢類型中，手寫的 TAG 基線始終能達到 40% 或更高的精確匹配準確率，而所有其他基準測試都無法超過 20% 的準確率。

### Queries

* Text2SQL 基線在所有基準測試中的表現都很差，執行準確率不超過 20%，但在排名查詢上的表現尤其差，準確率只有 10%， 因為許多排名查詢都需要對文字進行推理。
* RAG 在所有查詢類型中都無法正確回答任何一個查詢，突顯出它不適合此空間中的查詢。 添加 LLM 重新排名後，Retrieval + LLM Rank 可以在比較查詢中正確回答一個查詢，但其基準測試的表現仍然比 RAG 以外的所有其他查詢都差。

### Hand - Written TAG

* 手寫的 TAG 基線正確回答了 55% 的查詢，在比較查詢上的表現最佳，精確匹配準確率為 65%。 該基準測試在所有查詢類型（排名查詢除外）上的表現都很好，準確率超過 50%，原因是準確排序項目的難度較高。總體而言，與標準基準測試相比，這種方法使準確率提高了 20% 到 65%。
* 值得注意的是，除了提供更高的準確率外，手寫 TAG 方法還提供了一個高效的實現，執行時間比其他基準測試最多縮短了 3.1 倍。 手寫基準測試所有查詢的平均耗時為 2.94 秒。這個相對較低的執行時間突顯出，可以透過利用 LM 的高效批次推斷來設計一個高效的 TAG 系統。

## 相關研究

### Text2SQL

使用 LLM 的 Text2SQL 已在先前的工作中得到廣泛探索。WikiSQL、Spider 和 BIRD 都是跨域 Text2SQL 的熱門資料集。這些資料集包含許多領域的結構化資料，用於評估將自然語言查詢轉換為 SQL 的任務。然而，這個方向沒有利用模型超越 SQL 生成的能力，將需要推理或超出靜態資料來源的知識的查詢排除在範圍之外。

### RAG

增強生成（RAG）使 LLM 能夠擴展其參數知識到大型文字集合。SQuAD 和 HotPotQA 分別關注單文件和多文件源上的問答。密集表檢索（DTR）模型將 RAG 擴展到表格資料，將表格上下文嵌入以檢索與查詢相關的單元格和行。聯結感知表檢索在 DTR 模型中添加了表-表相似性分數項，以提高涉及聯結表的複雜查詢的性能。與先前的 RAG 工作相比，TAG 模型透過在查詢執行步驟中利用 LLM 功能，並允許 DBMS 對大量資料進行精確計算，涵蓋了使用者對其資料的更廣泛的查詢領域。

### 半結構化資料的自然語言查詢

先前的工作已經探索了半結構化資料來源中表格實體和非結構化實體欄位之間的關係資訊。STaRK 評估了半結構化知識庫 (SKB) 上的表格檢索方法，包括結構化和非結構化資訊。SUQL 解決了對話式搜尋的任務，其中 LLM 被用作語義解析器來處理使用者對混合資料的非結構化組件查詢。雖然這些工作主要關注半結構化資料上的自然語言搜尋查詢，但本文試圖探索更廣泛的查詢範圍，利用更多 LLM 功能來完成搜尋和查找以外的任務。

### 代理資料助理

最近的研究探索了作為資料助理的 LLM 代理。Spider2-V 探索了多模態代理在涉及程式碼生成和 GUI 控制的任務中的性能。雖然本文將 TAG 模型可處理地定義為 syn、exec 和 gen 函數的一次迭代，但未來的研究可能會探索在代理循環中擴展它。

## 結論

本文提出了表格增強生成 (TAG) 作為回答資料庫自然語言問題的統一模型。 本文開發了基準測試來研究兩種重要類型的查詢：需要世界知識的查詢和需要語義推理能力的查詢。系統評估證實，基準方法無法在這些任務上取得有意義的進展。然而，手寫的 TAG 管道可以實現高達 65% 的準確率，這表明構建 TAG 系統存在巨大的研究機會。
